## 二、客户体验视角

### 2.1 用户完整旅程

一位非技术用户（如业务主管、运营人员）在 HaGoKu 中上传数据并启动分析后，经历四个阶段：

```
Scout（字段理解）→ Cleaner（数据清洗）→ Analyst（统计分析）→ Reporter（生成报告）
```

Cleaner 是用户**第一次面对“数据被修改”的时刻**——此前 Scout 只是理解和命名字段，不碰数值。

**用户心理状态**：看到“清洗”二字，本能担心数据被篡改、样本被丢弃。Cleaner 卡片的**核心职责**是消除这种不安，让用户放心地进入后续分析。

**关键交互节点**：
1. 暂停在 Cleaner 卡片前
2. 扫一眼顶栏摘要 —— 行数是否少了？风险高不高？
3. 逐行看表格 —— 哪几列被改了？怎么改的？
4. 决定“确认继续”还是“提出疑问”

### 2.2 现状：用户实际看到什么？

前端 `CleaningReviewTable` 组件（`AnalyzePanel.tsx:302-387`）渲染内容：

```
┌─ Cleaner ───────────────────────────────────────────────────┐
│ 620 行（行数未变）· 偏差 low · 5 条 · 删行影响率 0.0%       │
├──────────┬──────────────┬────────┬──────────────────────────┤
│ 列       │ 策略         │ 影响行 │ 说明                     │
├──────────┼──────────────┼────────┼──────────────────────────┤
│ Inc1     │ winsorize    │   62   │ IQR检测到47个异常(7.6%)… │
│ Inc2     │ winsorize    │   62   │ IQR检测到47个异常(7.6%)… │
│ Bos1     │ winsorize    │   31   │ IQR检测到45个异常(7.3%)… │
│ Bos2     │ winsorize    │   31   │ IQR检测到21个异常(3.4%)… │
│ Bos3     │ winsorize    │   31   │ IQR检测到6个异常(1.0%)…  │
└──────────┴──────────────┴────────┴──────────────────────────┘
```

**非技术用户困惑路径复现**：

> *"Cleaner…是清洗数据。行数没变，那洗了什么？"*  
> *"`winsorize` 是什么？跟删除行有什么区别？"*  
> *"`偏差 low` — low 是好事还是坏事？低偏差意味着什么？"*  
> *"`删行影响率 0.0%` 说没删行，但 `影响行` 写 62 — 所以到底改没改？矛盾吗？"*  
> *"IQR…7.6%…这些数字在说什么？我需要去查 Google 吗？"*  
> *"5 列全都是同一种 `winsorize`，是出 bug 了还是本来就该这样？"*  
> *"我该点「确认继续」吗？看起来没问题……但我不确定。"*

**核心矛盾**：卡片的技术正确性（后端输出）与用户的信息安全感（前端感知）之间存在显著落差。

## 三、体验诊断与改进方案

### 3.1 诊断矩阵

| # | 问题 | 用户困惑 | 严重度 | 根因 |
|---|------|----------|--------|------|
| 1 | **策略字段为英文枚举** | “winsorize、drop_rows 是什么？” | 🟡 中 | 前端直接渲染 `strategy` 原始值 |
| 2 | **“影响率”与“影响行”概念矛盾** | “删行影响率 0%，但影响行 62？” | 🟡 中 | Winsorize 不删行但改写值，指标语义冲突 |
| 3 | **列名无中文映射** | “Inc1 是哪一列？Scout 给的中文名呢？” | 🟢 低 | Scout 字段表语义理解未传递至 Cleaner |
| 4 | **偏差评级缺解读** | “low 是好是坏？我需要做什么？” | 🟡 中 | 只输出标签未输出含义 |
| 5 | **说明过于技术** | “IQR、截断、7.6%——听不懂” | 🟡 中 | LLM prompt 未约束面向非技术用户 |
| 6 | **策略一致性未说明** | “5 列全用同一种方式，是 bug 吗？” | 🟢 低 | 无聚合概述 |

### 3.2 改进方案（按优先级）

#### P0 — 策略中文化（前端侧，30 分钟可落地）

在 `CleaningReviewTable` 组件添加 `strategyLabelMap`，渲染时优先展示中文：

```ts
const strategyLabelMap: Record<string, string> = {
  winsorize: "截尾修正",
  drop_rows: "删除行",
  drop_column: "删除列",
  fill_mean: "均值填充",
  fill_median: "中位数填充",
  fill_mode: "众数填充",
  fill_constant: "固定值填充",
  forward_fill: "前向填充",
  backward_fill: "后向填充",
  interpolate: "插值填充",
  multiple_imputation: "多重插补",
  flag_and_keep: "标记缺失",
};
```

渲染时：`{strategyLabelMap[r.strategy] ?? r.strategy}`

#### P1 — 说明字段人类化（后端 prompt 侧，1 小时可落地）

修改 `hagoku/agents/cleaner/prompt.md` 中 reason 字段约束：

> **每条 reason 需面向非技术用户，包含三层信息：**
> 1. 发现了什么问题（用通俗语言，不要用 IQR/Z-score 等术语）
> 2. 采用了什么方式处理（用中文策略名）
> 3. 对后续分析有什么好处
>
> 示例：
> - ❌ `IQR 检测到 47 个异常值（7.6%），Winsorize 截断优于删除`
> - ✅ `这列有 47 个极端值（占 7.6%），远超正常范围。我们将其恢复到合理边界内，保留全部样本，避免极端值干扰后续分析。`

同时修改偏差评级展示（前端 `CleaningReviewTable` 顶栏）：

```tsx
const biasHint: Record<string, string> = {
  low: "数据质量良好，异常值已温和修正",
  medium: "存在一定偏差，建议关注指定列的数据分布",
  high: "数据可能存在系统性偏差，请谨慎解读分析结论",
};
```

#### P2 — 概念消歧（前端 + 后端）

修改 `CleaningReport` 数据传递，将 `impact_rate` 重命名为更语义化的字段：
- 后端新增 `row_drop_rate`（仅计算真正删行的比例）
- 前端顶栏改为：「✅ 620 行完整保留」+「无行被删除」或「已删 X 行（占 Y%）」

#### P3 — 跨阶段字段标签传递（延后）

Scout 字段表 (`field_review`) 已包含 `chinese_name`，Cleaner 卡片可关联展示：每行列名优先显示中文，原始列名置灰为副行。

## 四、审查总结

| 维度 | 结论 | 行动建议 |
|------|------|----------|
| 硬编码风险 | **无风险。** 所有阈值均可配置，仅 2 处低优先暴露项 | 后续可暴露 `contamination` 和 Jaccard 阈值 |
| 数据完整性 | **无风险。** Winsorize 不丢样本，0% 删行率属正常表现 | 可增加“行级保留率”指标让用户直观感受 |
| 用户体验 | **有显著改进空间。** 策略英文、技术术语、概念歧义三处影响非技术用户信心 | 优先 P0（中文化，30min）+ P1（prompt 约束，1h） |
