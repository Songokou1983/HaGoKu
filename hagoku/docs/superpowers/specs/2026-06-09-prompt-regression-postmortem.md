## 根因分析

### 不是某一个 commit 的锅——是三层累积破坏

**层 1：上下文被删**（5/31 `f4d4e763`）

`knowledge_section`（跨项目知识）和 `command_context`（用户指令）从 Scout 系统提示词中消失。LLM 看不到历史经验和用户纠正——但当时行为还没明显退化，因为提示词本身的指令仍然是中性的。

**层 2：流程变结论**（6/1 `af0509e` + 6/3 `cd3c2c3`）

`used_in_analysis` 指令从"判断每个字段是否参与，说明原因"变成"只勾选直接回答分析目标必需的字段"。这是一个**结论性指令**——代码替 LLM 预设了"应该只选必需的"这个判断方向。LLM 变得过度保守，大量字段被排除。

**层 3：纠正通道被切断**（6/9 `bccdeca` + `fb488c3`）

用户纠正字段名后，LLM 原本会重新判断 `used_in_analysis`。这两个 commit 先删除了重判指令，再把 hint 改成"禁止重判"。用户纠正字段名的能力被完全切断——被层 2 排除的字段永远回不来。

### 为什么测试没拦住

`test_scout_prompt_contains_ignore_role_instruction` 诞生于层 2（6/8）。它验证"提示词是否含 ignore 关键词"——这正是层 2 污染提示词的**工具**。测试 RED → 加一句让测试 GREEN → 提示词被结论性指令污染 → LLM 行为退化 → 但测试仍然 GREEN。

**范畴错误**：用关键词匹配验证 LLM 行为。这就像用卡尺量体温——读数很精确，但体温不能这样量。

Cleaner 同理：`prompt.md` 从 36 行重写成 64 行，删掉了"推理链路"和"数据够了就提交"——但没有测试覆盖，冒烟测试只验证流程不 crash，LLM 判断退化无人察觉。

## 对提示词修改的理解

### 提示词 ≠ 代码

代码可以审计——看逻辑、跑测试、静态分析。测试 GREEN = 行为正确（大概率）。

提示词的"正确性"只有一种验证方式：**开着 dump 看 LLM 实际输出**。提示词是与人（LLM）多轮对话迭代出来的，其效果取决于 LLM 对自然语言的理解。删掉一句"啰嗦"的话可能恰好删掉了 LLM 需要的上下文线索。

### 破坏提示词的三种典型路径

| 路径 | 表现 | 案例 |
|------|------|------|
| **"优化"式破坏** | 觉得某段话多余、重复、不优雅 → 删掉 | 删 `knowledge_section`——LLM 失去跨项目记忆 |
| **"修 bug"式破坏** | LLM 行为异常（全选）→ 加限制性指令 → 行为走向另一个极端 | "只选必需的" → LLM 全部排除 |
| **"重构"式破坏** | 代码拆分时顺手删掉看起来不重要的拼接片段 | 删 `command_context`——用户纠正不生效 |

### 为什么提示词测试是危险的

```
测试框架对代码正确性验证非常强
     ↓
有人把同一套方法论套到提示词上
     ↓
assert "ignore" in prompt 诞生
     ↓
"prompt 缺 ignore → 加一句 → 测试 GREEN ✅"
     ↓
LLM 行为退化，但测试 GREEN，无人复查
     ↓
上线 → 用户发现崩溃
```

这类测试的致命缺陷：**测试 GREEN ≠ 行为正确，测试 RED ≠ 行为错误。** 完全没有信号价值，却有极强的负信号——它驱使开发者污染提示词来让测试变绿。

## 铁律 10 的设计逻辑

### 三道刹车

| 刹车 | 阻止什么 | 为什么有效 |
|------|---------|-----------|
| A: 禁止关键词测试 | 用 `assert "ignore" in prompt` 验证提示词 | 去掉错误的验证手段，开发者就不会被误导去污染提示词 |
| B: dump 对比门禁 | 无证据改提示词 | 把"看 LLM 实际输出"从建议变为强制 |
| C: 冒烟不充分声明 | 流程跑通就以为没事 | 明确冒烟测试的边界——只管 crash，不管判断 |

### 为什么是"刹车"而不是"流程"

流程（"改提示词必须先开 dump → 对比 → 提交"）依赖人的自律。刹车是硬门禁——不过闸门就动不了。

- 刹车 A 是**事前刹车**：不让你写那种测试，就不会被误导
- 刹车 B 是**事中刹车**：PR 没 dump 对比直接拒，不管你多自信
- 刹车 C 是**事后刹车**：冒烟 GREEN 不够，必须额外人工看 dump

### 正向修复原则

铁律 -1 说了"只做正向修复，不做回滚"。这次修复正是这个原则的实践：

- 不回滚 commit，而是把正确的提示词从历史版本**抄回来**
- 不是简单 revert，而是理解旧版为什么对、新版为什么错之后，手工恢复正确的部分
- 同时修正旧版的问题（MiniMax 全选）：旧版 hint 说"对照分析目标判断是否直接相关"太模糊 → 新版改成"逐字段重判，只判断当前字段"
